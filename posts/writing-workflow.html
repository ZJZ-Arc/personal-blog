我的写作流程：Markdown 写，HTML 发

把写作和排版拆成两半：想内容时只用 Markdown，发布时才碰 HTML。

2026年10月8日
阅读时长: — 分钟

写博客最容易劝退人的其实不是技术，是「打开编辑器之后要面对一堆 HTML 标签」这件事。 所以我把写作和排版拆成了两半：想内容的时候只用 Markdown，发布的时候才碰 HTML。

第一步：在 drafts/ 里用 Markdown 写

在项目根目录建一个 drafts/ 文件夹放草稿，并且把它加进 .gitignore—— 草稿不该被推上公开仓库。这个文件夹里的文件长这样： 

---
title: 我的写作流程
date: 2026-10-08
tags: 教程 工具
summary: 一句话说清楚这篇讲什么，会出现在首页卡片上。
---

正文从这里开始，用 Markdown 写就好。

## 一个小标题

- 列表项
- 另一个列表项

开头那段被 --- 包起来的东西叫 front matter， 很多博客工具（Hexo、Hugo、Astro）都认这个格式——也就是说， 将来你迁移到框架时，这批草稿可以原样复用。

第二步：转成 HTML 片段

三种方式，按你顺手的挑一种：

  1. 编辑器导出。Typora、VS Code 的 Markdown 预览都能复制成 HTML， 或者用 VS Code 的 Markdown: Print current document to HTML。
  2. 命令行转换。装了 Node 的话，一行命令就够，不用全局安装任何东西： 
    npx marked -i drafts/my-post.md -o body.html
  3. 直接手写 HTML。听起来最麻烦，实际上文章以段落和列表为主时， 写起来的差别没有想象中大，而且你能完全控制语义。

第三步：套进模板生成页面

项目里带了一个零依赖的小脚本，它会读取 templates/post.html， 把标题、日期、标签填进去，输出到 posts/： 

node tools/new-post.mjs \
  --title "我的写作流程" \
  --date 2026-10-08 \
  --tags "教程 工具" \
  --summary "一句话说清楚这篇讲什么。"

它用的是 Node 自带的能力，不需要 npm install。 生成的页面里正文位置留了一个明显的注释标记，把上一步得到的 HTML 贴进去就行。

第四步：发布清单

零依赖方案的代价就是这份清单，每次发新文章照着走一遍，两分钟够了：

  • 在 index.html 的文章列表里加一个卡片（新文章放最上面）；
  • 如果用了新标签，在 index.html 的标签栏和 tags.html 里各加一条，并更新数量；
  • 在 feed.xml 里加一个 <item>，更新 lastBuildDate；
  • 在 sitemap.xml 里加一个 <url>；
  • 跑一遍 node tools/check.mjs，让机器替你检查上面四条有没有漏；
  • 再人眼确认一次：双击首页，深色浅色都切一下、点标签筛一下、点进文章再回来；
  • git add . && git commit -m "post: 我的写作流程" && git push。
建议把这份清单直接抄进项目的 README。半年后你一定会忘，而忘了清单的后果是 首页有链接、RSS 里没有——读者从订阅器里根本看不到你的新文章。

一点经验

写完当天就发，不要在细节上磨。我删掉过太多「再改改就发」的稿子， 而它们的问题往往不是文字不好，是我在没有读者的情况下反复修改同一段话。 发布才是真正的编辑过程。
